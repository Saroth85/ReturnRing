# data/

Everything here is generated or downloaded and is not committed.

- `raw/asos/` — the six ASOS GraphReturns pickles (CC BY 4.0), checked against the sha256
  values pinned in `pipeline/ingest/asos_download.py` (ADR-10). `MANIFEST.json` is a log only.
- `raw/asos_{events,customers,variants}.parquet` — the same data under the raw contracts of
  ADR-13, written by `python -m pipeline.ingest` with provenance (nature: real).
- `raw/asos_profile.txt` — the plain-text profile of the raw tables (US-101).
- `store/` — synthetic store Navigli Fashion: `python -m pipeline.generator --calibration <json>
  --out data --seed 42` or `make generate` (docs/synthetic-store.md).
- `truth/` — ground truth of the generator. Running services (api, ui, demo) never read it; only
  offline training and evaluation jobs do (CLAUDE.md rule 12).
- `ood/store/` and `truth/ood/truth/` — out-of-distribution scenario (`--scenario ood`, US-105): its
  store, and its ground truth inside `truth/` with every other ground truth. Never used in training:
  the evaluation reads it and reports it on a separate row.
- `features/` and `ood/features/` — as-of tables of phase 2 (ADR-13): `links` and `clusters`
  (`make graph`, US-203), `customer_features`, `customer_value` and `evidence_quality`
  (`make features`, US-205/206/209), `product_anomalies` (`make anomalies`, US-208). Each file's
  lineage (`returnring.lineage`) ends with the origin of the store it was computed from; a job
  refuses a table built from another store.
- `features/customer_embeddings` and `ood/features/customer_embeddings` — the GraphSAGE customer
  embeddings of `make embeddings` (US-202, docs/graphsage.md). The job needs PyTorch
  (`infra/requirements-gnn-cpu.txt`) and is not part of `make pipeline`; `make risk` runs the A4
  row of the ablation only when this file exists, and reports A4 as not run otherwise.
- `scores/` — `scores` and `request_scores` of the batch scoring (`make risk`, or `make score`
  with the saved models), with the thresholds of every quadrant (US-204).
- `gpu-synthetic/` (optional) — the main store regenerated by hand (seed 42, scale 1.0) with its
  graph and features for the AMD training session of 16 Oct 2026
  (docs/amd-training-session-2026-10-16.md). No make target writes or reads it.

## How the folder is written

`make pipeline` writes everything above except `raw/`, `customer_embeddings` and
`gpu-synthetic/`, from the committed real calibration, in this order:
`generate generate-ood graph features anomalies risk serving`. The last step writes the serving
snapshot the API reads (ADR-16) to `serving/` at the repository root, outside this folder; it holds
no ground truth. `make demo-data` runs the same chain in the `pipeline` job container, without
rewriting `docs/results/`.

The models go to `artifacts/risk/models`; the offline evaluation outputs (metrics, graph
evaluation, fairness) to `artifacts/eval/`, which holds counts and metrics, never a customer listed
with its ground truth.

The offline reports in `docs/results/` are generated; each is rewritten by one command, never by
hand:

| Command | Rewrites | Reads |
| --- | --- | --- |
| `make results` | `account-graph.md`, `customer-quantities.md`, `us-208-product-anomalies.md` | the main and OOD stores and `truth/` |
| `make risk` | `us-204-risk.md` | both stores with their features, and `truth/` |
| `make propensity` | `us-201-propensity.md` | `raw/` (real ASOS tables, `make asos`) |
| `make gnn-results` | `us-202-graphsage.md` | `artifacts/eval/gnn/` (`make gnn-asos`, `make embeddings`) and `artifacts/eval/risk/metrics.json` (`make risk`) |

## ASOS download

`make asos` downloads the six pickles from OSF (https://osf.io/c793h), verifies them, converts them
and writes the profile and the calibration (US-101); `make asos SOURCE_DIR=<dir>` takes them from a
local copy, and `make asos-verify` checks the pinned sha256 values only. Only `make propensity` and
`make gnn-asos` need `raw/`. OSF answered HTTP 503 on both download attempts of 16 Oct 2026
(docs/amd-training-session-2026-10-16.md), so the AMD session trained on the synthetic store only.

The synthetic store needs no download. The generator calibration made from the ASOS train split
holds aggregates only, so it is committed outside this folder:
`pipeline/calibration/asos_calibration.json`. `make asos` rewrites that file from the downloaded
tables.
